# Телеграм-агент аналитики по Битрикс24

Бот на Python, который подключается к облачному Битрикс24 по входящему вебхуку,
считает вашу личную статистику и присылает её **готовым файлом** (Excel, CSV или
JSON) в ответ на запрос в свободной форме.

```
Вы:  сколько задач я закрыл за прошлую неделю
Бот: Отчёт по Битрикс24 — Петров Иван
     Период: прошлая неделя (03.08.2026 — 09.08.2026)

     Задачи
     • закрыто: 17 задач
     • поставлено за период: 21
     • сейчас не закрыто: 9
        ◦ Выполняется: 5
        ◦ Ждёт выполнения: 3
        ◦ Ждёт контроля: 1
     • просрочено: 2
     • среднее время закрытия: 6 ч 12 мин (медиана 3 ч 40 мин)

     [bitrix24_petrov_ivan_20260803-20260809.xlsx]
```

## Что считает бот

**Задачи**

- закрыто за период и поставлено за период;
- сколько задач не закрыто прямо сейчас и в каких они статусах
  (выполняется, ждёт выполнения, ждёт контроля, отложена);
- распределение незакрытых задач по стадиям канбана и по проектам;
- среднее, медианное и 90-й персентиль времени закрытия задачи;
- сколько закрыто в срок и с просрочкой, сколько просрочено сейчас;
- списанное в задачах рабочее время;
- динамика закрытия по дням и детализация по каждой задаче со ссылками на портал.

**Открытые линии**

- сколько обращений обработано и сколько из них закрыто;
- среднее и медианное время до первого ответа;
- **среднее время решения вопроса** (и медиана с 90-м персентилем);
- оценки клиентов (CSAT): лайки, дизлайки, доля положительных;
- выполнение SLA первого ответа;
- разбивка по каналам (чат на сайте, Telegram, WhatsApp и т.д.), по линиям,
  по дням и по часам суток;
- детализация по каждому обращению.

## Как это работает

```
Telegram ──▶ aiogram ──▶ разбор запроса (период, разделы, формат)
                              │
                              ▼
                   AnalyticsService ──▶ REST API Битрикс24
                              │          tasks.task.list, tasks.task.stages.get,
                              │          imopenlines.v2.*, crm.activity.list, user.get
                              ▼
                     метрики ──▶ XLSX / CSV / JSON ──▶ файл в чат
```

Структура кода:

| Каталог | Назначение |
|---|---|
| `b24agent/bitrix/` | клиент REST API и репозитории задач, открытых линий, пользователей |
| `b24agent/analytics/` | периоды, расчёт метрик, сборка отчёта |
| `b24agent/nlu/` | разбор запроса на естественном языке |
| `b24agent/reports/` | генерация XLSX, CSV, JSON и текстовой сводки |
| `b24agent/bot/` | хендлеры, клавиатуры, контроль доступа |
| `b24agent/storage/` | SQLite: привязка чата к сотруднику, история запросов |

## Установка

### 1. Входящий вебхук в Битрикс24

Портал → **Разработчикам** → **Другое** → **Входящий вебхук**. Отметьте права:

| Право | Зачем |
|---|---|
| `task` | задачи, стадии канбана |
| `imopenlines` | обращения открытых линий |
| `user` | имена сотрудников |
| `crm` | обходной путь по обращениям, если статистика открытых линий недоступна |
| `sonet_group` (Рабочие группы) | названия проектов |

Скопируйте адрес вида
`https://ваш-портал.bitrix24.ru/rest/1/xxxxxxxxxxxxxxxx/`.

> Важно: статистика считается в пределах прав пользователя, от имени которого
> создан вебхук. Чтобы видеть данные другого сотрудника, вебхук должен создать
> он сам либо руководитель с доступом к его задачам и линиям.

### 2. Бот в Telegram

Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → скопируйте токен.

### 3. Запуск

```bash
git clone <этот-репозиторий>
cd bitrix24_agent

cp .env.example .env
# впишите TELEGRAM_BOT_TOKEN и BITRIX_WEBHOOK_URL

python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python run.py
```

Первым сообщением боту отправьте `/id`, впишите полученный номер в
`TELEGRAM_ALLOWED_USER_IDS` и перезапустите — иначе отчёты сможет запросить
любой, кто найдёт бота.

### Запуск в Docker

```bash
cp .env.example .env   # заполните токен и вебхук
docker compose up -d --build
docker compose logs -f
```

База и файлы отчётов сохраняются в каталоге `./data`.

## Проверка без Telegram

Полезно при настройке — сразу видно, хватает ли прав вебхуку:

```bash
python -m b24agent.cli "задачи за прошлый месяц"
python -m b24agent.cli "обращения в открытой линии за июнь" --format csv
python -m b24agent.cli "полный отчёт за неделю" --user-id 42 --out /tmp/report.xlsx
```

## Как формулировать запросы

Разбор офлайновый и правиловый: внешние сервисы не нужны, ответ предсказуем.

**Период**

| Формулировка | Период |
|---|---|
| `сегодня`, `вчера`, `позавчера` | сутки |
| `за неделю`, `на этой неделе` | с понедельника по сегодня |
| `за прошлую неделю` | предыдущая календарная неделя целиком |
| `за месяц`, `в этом месяце` | с 1-го числа по сегодня |
| `за прошлый месяц` | предыдущий календарный месяц |
| `за квартал`, `за прошлый квартал`, `за год`, `за прошлый год` | соответственно |
| `за последние 14 дней`, `за последние 3 месяца` | скользящее окно |
| `за июнь`, `в декабре 2025` | конкретный месяц |
| `с 01.06.2026 по 30.06.2026` | произвольные даты |

Без указания периода берётся текущий месяц.

**Разделы.** Слова «задача», «дедлайн», «просрочено» включают раздел задач;
«стадия», «канбан», «этап» добавляют разбивку по стадиям; «линия», «обращение»,
«чат», «оператор», «оценка» — раздел открытых линий. Если подсказок нет, отчёт
собирается целиком.

**Формат.** По умолчанию Excel. Допишите «в csv» или «в json», либо задайте
формат по умолчанию командой `/format`. Фразы «только сводка», «без деталей»
убирают из файла листы с построчной детализацией.

## Команды

| Команда | Действие |
|---|---|
| `/report` | отчёт за текущий месяц |
| `/link 42` | считать статистику по сотруднику с ID 42 (`/link 0` — сброс) |
| `/whoami` | по кому сейчас считается отчёт и в каком формате |
| `/format xlsx\|csv\|json` | формат файла по умолчанию |
| `/history` | последние запросы |
| `/id` | ваш Telegram ID (для списка доступа) |
| `/help` | справка |

## Настройки (`.env`)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | токен от @BotFather (обязательно) |
| `TELEGRAM_ALLOWED_USER_IDS` | пусто | Telegram ID через запятую; пусто = без ограничений |
| `BITRIX_WEBHOOK_URL` | — | адрес входящего вебхука (обязательно) |
| `BITRIX_DEFAULT_USER_ID` | владелец вебхука | по кому считать статистику по умолчанию |
| `TIMEZONE` | `Europe/Moscow` | часовой пояс расчёта периодов |
| `BITRIX_RATE_LIMIT` | `2` | запросов в секунду к REST |
| `BITRIX_TIMEOUT` | `30` | таймаут запроса, секунды |
| `BITRIX_MAX_RECORDS` | `5000` | предохранитель от выгрузки слишком широкого периода |
| `DATABASE_PATH` | `./data/bot.sqlite3` | файл SQLite |
| `REPORTS_DIR` | `./data/reports` | каталог отчётов консольного режима |
| `DEFAULT_REPORT_FORMAT` | `xlsx` | формат файла по умолчанию |
| `LOG_LEVEL` | `INFO` | уровень логирования |

## Особенности данных Битрикс24

Эти нюансы влияют на трактовку цифр, поэтому они вынесены в отчёт явно.

**Задачи фильтруются по `REAL_STATUS`.** В `tasks.task.list` поле `STATUS` —
мета-фильтр (`-1` просрочена, `-2` не просмотрена, `-3` почти просрочена), и
запрос `STATUS=5` завершённые задачи не вернёт. Бот использует `REAL_STATUS`.

**Стадия — срез на сейчас.** REST не отдаёт историю переходов между стадиями,
поэтому распределение по стадиям и «сколько в работе» — это состояние на момент
отчёта, а не событие внутри периода. Закрытые и поставленные задачи, наоборот,
считаются по датам `CLOSED_DATE` и `CREATED_DATE` внутри периода.

**Открытые линии: два источника.** Основной — методы статистики
`imopenlines.v2.*` (обновление `imopenlines 26.700.0`, право
`report_open_lines`): они дают хранимые метрики времени ответа и решения, CSAT
и агрегаты, посчитанные порталом. Если обновление ещё не пришло на портал или
тариф не включает статистику открытых линий, бот сам переключается на
приблизительный подсчёт по делам CRM (`crm.activity.list`, провайдер
`IMOPENLINES`) и пишет об этом в примечаниях к отчёту — время решения в этом
случае оценивается как разница между созданием и завершением дела.

**Лимит частоты запросов.** Портал ограничивает REST примерно двумя запросами в
секунду; клиент держит token bucket, повторяет запросы при
`QUERY_LIMIT_EXCEEDED` и группирует однотипные вызовы через `batch`.

## Разработка

```bash
pip install -r requirements-dev.txt
pytest -q          # 102 теста, сеть не нужна
ruff check .
```

Тесты работают на поддельном портале Битрикс24 (`httpx.MockTransport`) и
поддельной сессии Bot API, поэтому проверяются и сценарии бота целиком: от
текста запроса до отправленного файла.
