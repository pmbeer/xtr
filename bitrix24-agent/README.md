# Bitrix24 Agent — агент анализа личной продуктивности в Битрикс24

Консольный агент, который подключается к вашему порталу Битрикс24 через
**входящий вебхук** и собирает отчёт о вашей продуктивности за выбранный
период:

- сколько задач вы закрыли и сколько задач сейчас в работе, с разбивкой по
  стадиям (ждёт выполнения / выполняется / ждёт контроля / отложена и т.д.);
- сколько задач просрочено прямо сейчас;
- среднее время выполнения закрытых задач;
- сколько обращений в Открытых линиях вы обработали, сколько ещё в работе;
- среднее время решения обращения в Открытой линии.

Агент использует **только официальный REST API Битрикс24**
(https://apidocs.bitrix24.com/) через ваш собственный вебхук — никакие
данные не отправляются в сторонние сервисы. Подробнее про важное
ограничение по Открытым линиям — см. раздел [«Про Открытые линии и
CRM»](#про-открытые-линии-и-crm) ниже.

## Установка

```bash
cd bitrix24-agent
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```

## Настройка

1. В Битрикс24 откройте **Разработчикам → Другое → Входящий вебхук**.
2. Дайте вебхуку права как минимум на модули: `task` (Задачи), `crm` (CRM),
   `im` (для уведомлений и определения текущего пользователя), `user`.
3. Скопируйте `.env.example` в `.env` и заполните:

```bash
cp .env.example .env
```

```dotenv
BITRIX24_WEBHOOK_URL=https://ваш-портал.bitrix24.ru/rest/1/xxxxxxxxxxxxxxxxxxxxxxxx/
BITRIX24_USER_ID=123        # ID пользователя, чью продуктивность анализируем
BITRIX24_TZ_OFFSET=+03:00   # часовой пояс для расчёта периодов
BITRIX24_NOTIFY=false       # true — присылать отчёт себе в Битрикс24 после каждого запуска
```

Если `BITRIX24_USER_ID` не указан, агент определит текущего пользователя
вебхука через `user.current`.

## Использование

```bash
bitrix24-agent --period week
bitrix24-agent --period month --format markdown
bitrix24-agent --period 2026-08-01:2026-08-12 --format json
bitrix24-agent --period today --notify   # + отправит отчёт вам в Битрикс24
```

Доступные пресеты периода: `today`, `yesterday`, `week`, `last_week`,
`month`, `last_month`, `quarter`, `year`, `all`, а также произвольный
диапазон `YYYY-MM-DD:YYYY-MM-DD`.

Пример вывода (`--format text`):


## Автоматический запуск (агент по расписанию)

Чтобы получать отчёт регулярно без ручного запуска, добавьте задачу в cron.
Например, ежедневный отчёт по будням в 19:00 с отправкой себе в Битрикс24:

```cron
0 19 * * 1-5 cd /path/to/bitrix24-agent && .venv/bin/bitrix24-agent --period today --notify >> /var/log/bitrix24-agent.log 2>&1
```

Или еженедельный отчёт по понедельникам за прошлую неделю:

```cron
0 9 * * 1 cd /path/to/bitrix24-agent && .venv/bin/bitrix24-agent --period last_week --notify >> /var/log/bitrix24-agent.log 2>&1
```

## Метрики: как они считаются

### Задачи (`tasks.task.list`)

- **Стадии** — фактический статус задачи в поле `REAL_STATUS`
  (`2` — ждёт выполнения, `3` — выполняется, `4` — ждёт контроля,
  `5` — завершена, `6` — отложена). Текущий снимок по стадиям берёт только
  активные задачи (без завершённых/отклонённых), чтобы не тянуть всю историю.
- **Закрыто за период** — задачи с `REAL_STATUS=5`, у которых `CLOSED_DATE`
  попадает в выбранный период.
- **Среднее время выполнения** — среднее `CLOSED_DATE - CREATED_DATE` по
  закрытым за период задачам.
- **Просрочено сейчас** — задачи с мета-статусом `STATUS=-1` (не зависит от
  выбранного периода, это состояние "здесь и сейчас").

### Открытые линии (`crm.activity.list`, провайдер `IMOPENLINES_SESSION`)

## Про Открытые линии и CRM

Официальный классический REST API Битрикс24 **не предоставляет отдельного
метода** для получения агрегированной статистики по обращениям в Открытых
линиях (кол-во диалогов, время ответа/решения по операторам) без установки
дополнительного приложения из Маркетплейса.

Рабочий и полностью официальный способ получить эти цифры через REST — это
диалоги Открытых линий, привязанные к CRM. Если в настройках линии включена
привязка к CRM (создание лида/сделки/контакта на входящее обращение),
Битрикс24 создаёт для каждого диалога CRM-активность с
`PROVIDER_ID = "IMOPENLINES_SESSION"`. Агент читает эти активности через
`crm.activity.list` и считает:

- **Всего обращений** — количество таких активностей за период (по полю
  `CREATED`), назначенных на пользователя (`RESPONSIBLE_ID`);
- **Обработано (закрыто)** — активности с `COMPLETED = 'Y'`;
- **В работе сейчас** — оставшиеся, незавершённые;
- **Среднее время решения** — среднее `END_TIME - START_TIME` по закрытым
  обращениям.

**Ограничение**: если ваша Открытая линия работает без привязки к CRM,
обращения не создают такую активность — и, к сожалению, никакой другой
официальный REST-метод не отдаёт список таких диалогов за период. В этом
случае варианты:

1. Включить привязку к CRM в настройках линии (Контакт-центр → ваша линия →
   настройки → «Создавать в CRM» и т.п.) — тогда агент начнёт видеть новые
   обращения.
2. Смотреть встроенный отчёт Битрикс24: **CRM → Аналитика → Открытые
   линии** — там статистика считается на стороне Битрикс24 без REST.
3. Использовать приложение из Маркетплейса Битрикс24, которое официально
   предоставляет такую статистику через свой REST-интерфейс (некоторые
   коробочные редакции и партнёрские решения дают модуль отчётов по
   Открытым линиям).

### О стороннем домене `vibecode.bitrix24.tech`

При поиске решения в интернете можно наткнуться на сторонний домен
`vibecode.bitrix24.tech`, который предлагает "удобные" REST-методы вида
`POST /v1/openlines/stats`, `imopenlines.v2.Stat.get` и т.п. через **отдельный
API-ключ**. Мы проверили: таких методов нет в официальной документации
`apidocs.bitrix24.com` (прямой запрос возвращает 404), это сторонний сервис,
который потребовал бы передавать данные вашего портала через **его**
API-ключ, а не через ваш собственный вебхук. Этот проект **не использует** и
не рекомендует использовать этот домен — весь код работает исключительно с
вашим собственным порталом через документированные официальные методы
`apidocs.bitrix24.com`.

## Структура проекта

```
bitrix24-agent/
├── bitrix24_agent/
│   ├── client.py           # низкоуровневый REST-клиент (вебхук, пагинация, ретраи)
│   ├── config.py           # загрузка настроек из .env
│   ├── period.py           # пресеты периодов (today/week/month/...)
│   ├── tasks_report.py     # аналитика по задачам
│   ├── openlines_report.py # аналитика по Открытым линиям
│   ├── report.py           # сборка и рендер отчёта (text/markdown/json)
│   └── cli.py              # консольный интерфейс
└── tests/                  # unit-тесты (pytest + responses, без реальных запросов)
```

## Безопасность

- Вебхук хранит доступ к вашему порталу — держите `.env` вне репозитория
  (файл уже добавлен в `.gitignore`) и не публикуйте его.
- Ограничьте права вебхука минимально необходимым набором модулей
  (`task`, `crm`, `im`, `user`).
- При необходимости отозвать доступ — удалите вебхук в настройках портала.
