# Telegram-агент аналитики Bitrix24

Бот по запросу собирает персональную статистику из облачного Bitrix24 и отправляет
Excel-файл. В отчёт входят:

- завершённые за период и текущие активные задачи;
- распределение активных задач по статусам и стадиям;
- количество просроченных задач;
- обработанные, закрытые и активные обращения Открытых линий;
- среднее время первого ответа и решения обращения;
- отдельные листы с активными и завершёнными задачами.

Бот только читает данные. Доступ к нему ограничен списком Telegram user ID.

## Подготовка Bitrix24

1. Откройте `Разработчикам → Другое → Входящий вебхук`.
2. Создайте вебхук от имени сотрудника, отчёт которого нужен.
3. Выдайте права `Задачи (task)`, `Пользователи (user)` и
   `Открытые линии (imopenlines)`.
4. Для статистики Открытых линий тариф и роль сотрудника должны включать право
   просмотра статистики. Используется метод `imopenlines.v2.Stat.get`.

Если новый API статистики ещё недоступен на портале, бот сформирует остальные листы
и укажет ошибку в строке «Открытые линии».

## Настройка Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather).
2. Узнайте свой числовой Telegram user ID, например у `@userinfobot`.
3. Скопируйте `.env.example` в `.env` и заполните:

```bash
cp .env.example .env
```

Обязательные параметры:

```dotenv
TELEGRAM_BOT_TOKEN=...
TELEGRAM_ALLOWED_USER_IDS=123456789
BITRIX24_WEBHOOK_URL=https://example.bitrix24.ru/rest/1/secret/
```

Секреты не следует коммитить в Git.

## Запуск

Через Docker:

```bash
docker compose up -d --build
```

Локально:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .
bitrix24-agent
```

## Запросы

- `отчёт за сегодня`
- `отчёт за эту неделю`
- `отчёт за прошлый месяц`
- `отчёт за последние 14 дней`
- `отчёт с 01.08.2026 по 10.08.2026`
- `/report` — текущий месяц

Даты и границы периода вычисляются в часовом поясе `REPORT_TIMEZONE`.

### Ограничения

«Завершено задач» означает задачи, где сотрудник был исполнителем и дата закрытия
попала в выбранный период. Полный аудит каждого изменения требует отдельного
приложения Bitrix24 с обработчиками событий и постоянным хранилищем; входящий вебхук
не предоставляет ретроспективный журнал всех действий.
