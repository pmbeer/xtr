# Личный дашборд Битрикс24

Самостоятельный дашборд для одного сотрудника. Сервер получает данные через входящий вебхук Битрикс24, а браузер видит только готовые агрегированные показатели.

## Что показывает

- число закрытых задач за период;
- активные и просроченные задачи, а также распределение по статусам;
- последние завершённые задачи;
- обработанные и активные сессии Открытых линий;
- среднее время от создания до закрытия сессии.

В задачах учитываются только задачи, где текущий пользователь вебхука — ответственный. Сессия Открытой линии считается обработанной, если Битрикс24 вернул дату её закрытия.

## Подключение

1. В Битрикс24 откройте **Разработчикам → Другое → Входящий вебхук**.
2. Создайте вебхук от имени анализируемого пользователя и выдайте права как минимум на **Задачи** и **Пользователь**. Для метрик Открытых линий добавьте доступ к **Открытым линиям**.
3. Скопируйте `.env.example` в `.env` и вставьте полный URL вебхука:

   ```bash
   cp .env.example .env
   ```

   ```ini
   BITRIX_WEBHOOK_URL=https://portal.bitrix24.ru/rest/1/секретный_токен/
   DASHBOARD_USERNAME=dashboard
   DASHBOARD_PASSWORD=длинный-уникальный-пароль
   ```

4. Запустите сервис:

   ```bash
   npm start
   ```

5. Откройте `http://localhost:3000`.

Используйте HTTPS и не оставляйте публичный дашборд без `DASHBOARD_USERNAME` и `DASHBOARD_PASSWORD`. Файл `.env` игнорируется Git.

## Особенности и ограничения

- Данные обновляются при открытии страницы; на 60 секунд используется серверный кэш, чтобы не перегружать REST API.
- Метрика среднего времени решения доступна только если вебхук имеет право читать сессии Открытых линий и API возвращает `DATE_CREATE` и `DATE_CLOSE`.
- Это текущая аналитика по данным Битрикс24, а не журнал всех действий. Для неизменяемой исторической аналитики (например, изменения стадии и первого ответа) потребуется отдельное хранилище и плановая синхронизация или обработчик событий.
