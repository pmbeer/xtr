# Bitrix24 Report Bot

Telegram-бот на Python, который подключается к облачному порталу Битрикс24 по
входящему вебхуку и по вашему запросу собирает отчёт о вашей активности:

- сколько задач вы закрыли за период;
- сколько задач у вас сейчас в работе и на каких стадиях они находятся;
- сколько просроченных задач;
- сколько обращений в Открытых линиях вы обработали и среднее время решения обращения.

По запросу (просто напишите период текстом — «сегодня», «неделя», «прошлый
месяц», конкретные даты и т.п.) бот присылает готовый Excel-файл (`.xlsx`) с
подробной детализацией по всем метрикам плюс короткое резюме прямо в чате.

## Как это работает

```
Telegram-пользователь → бот (aiogram) → REST API Битрикс24 (входящий вебхук)
                                       → агрегация статистики (задачи + CRM-дела Открытых линий)
                                       → Excel-отчёт (openpyxl) → отправка файла в Telegram
```

Данные о задачах берутся методом `tasks.task.list`. Статистика по Открытым
линиям строится на основе CRM-дел (`crm.activity.list`,
`PROVIDER_ID = IMOPENLINES_SESSION`), которые Битрикс24 автоматически создаёт
для каждой сессии диалога, привязанной к CRM (это поведение по умолчанию,
подробнее — в разделе про [ограничения](#ограничения-и-особенности-статистики-открытых-линий)).

## Требования

- Python 3.11+ (проверено на 3.12) — при запуске без Docker;
- либо Docker + Docker Compose — для запуска в контейнере;
- облачный портал Битрикс24 с включённым REST API (доступен на коммерческих
  тарифах; на бесплатном тарифе REST API может быть ограничен);
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather).

## Шаг 1. Создать вебхук в Битрикс24

1. В левом меню Битрикс24 откройте **Приложения → Разработчикам** (Developer
   resources).
2. На вкладке **Готовые решения → Прочее** выберите **Входящий вебхук**
   (Incoming webhook).
3. В блоке **Назначить права** включите как минимум:
   - `task` — задачи (для статистики по задачам);
   - `crm` — CRM (для статистики Открытых линий через CRM-дела);
   - `user` — пользователи (чтобы узнавать свой `BITRIX_DEFAULT_USER_ID`);
   - `imopenlines` — Открытые линии (не обязательно, но пригодится, если
     захотите расширить бота).
4. Сохраните вебхук и скопируйте итоговый URL — он выглядит так:
   `https://yourcompany.bitrix24.ru/rest/1/xxxxxxxxxxxxxxxx/`.
5. Узнайте свой `ID` пользователя в Битрикс24 (число в адресе профиля
   `/company/personal/user/<ID>/` или через вызов метода `user.current` в
   этом же конструкторе запросов) — обычно это ID того, кто создал вебхук.

## Шаг 2. Создать Telegram-бота

1. Напишите [@BotFather](https://t.me/BotFather) команду `/newbot` и следуйте
   инструкциям — получите `TELEGRAM_BOT_TOKEN`.
2. Узнайте свой Telegram `user_id`, написав, например,
   [@userinfobot](https://t.me/userinfobot) — потребуется для
   `TELEGRAM_ALLOWED_USER_IDS`, чтобы кроме вас никто не мог получить доступ к
   вашей рабочей статистике.

## Шаг 3. Настроить и запустить

```bash
cd bitrix24-report-bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# откройте .env и заполните TELEGRAM_BOT_TOKEN, BITRIX_WEBHOOK_URL,
# BITRIX_DEFAULT_USER_ID, TELEGRAM_ALLOWED_USER_IDS

python run.py
```

Бот запустится в режиме long polling — держите процесс запущенным (например,
через `systemd`, `tmux`/`screen` или Docker, см. ниже).

## Запуск в Docker

```bash
cd bitrix24-report-bot
cp .env.example .env
# заполните .env

docker compose up -d --build
docker compose logs -f
```

## Использование бота

1. Напишите боту `/start` — он покажет краткую инструкцию и клавиатуру с
   типовыми периодами.
2. Отправьте период отчёта текстом (или нажмите кнопку на клавиатуре),
   например:
   - `сегодня`, `вчера`, `позавчера`;
   - `неделя` (последние 7 дней), `эта неделя`, `прошлая неделя`;
   - `месяц` (последние 30 дней), `этот месяц`, `прошлый месяц`;
   - `квартал`, `прошлый квартал`, `год`;
   - конкретные даты: `01.08.2026-12.08.2026`, `с 1 по 12 августа 2026`, `05.08`.
3. Бот пришлёт сообщение о том, что готовит отчёт, а затем — файл `.xlsx` с
   листами:
   - **Сводка** — ключевые метрики и разбивка задач по стадиям;
   - **Задачи в работе** — список текущих задач (просроченные подсвечены);
   - **Закрытые задачи** — список задач, закрытых за период, с временем
     выполнения;
   - **Открытые линии** — список обращений с временем обработки.

Также доступна команда `/report <период>`, работающая так же, как обычное
текстовое сообщение — удобно для скриптов или быстрого повторного запроса.

## Несколько пользователей

По умолчанию бот показывает статистику пользователя `BITRIX_DEFAULT_USER_ID`
всем, кому разрешён доступ. Если ботом пользуется несколько сотрудников и
каждому нужна *своя* статистика, задайте `TELEGRAM_TO_BITRIX_USER_MAP` в
`.env` — JSON-словарь `{"<telegram_user_id>": <bitrix_user_id>, ...}`.
Например:

```
TELEGRAM_TO_BITRIX_USER_MAP={"111111111": 5, "222222222": 8}
```

Для пользователей, не указанных в словаре, используется
`BITRIX_DEFAULT_USER_ID`.

## Ограничения и особенности статистики Открытых линий

У Битрикс24 на момент разработки бота нет отдельного публичного REST-метода,
который отдавал бы готовую агрегированную статистику оператора Открытых линий
(количество обращений, среднее время ответа/решения) напрямую. Поэтому бот
использует альтернативный, но официально документированный путь: CRM-дела с
`PROVIDER_ID = IMOPENLINES_SESSION`, которые Битрикс24 создаёт автоматически
для каждой сессии диалога, привязанной к элементу CRM (лид, сделка, контакт,
компания) — то есть при обычной работе с Контакт-центром / Открытыми линиями.

Из этого следуют два практических момента:

- если у вашего портала отключена или не настроена связка "Открытые линии →
  CRM", раздел статистики по обращениям в отчёте будет пустым — это
  особенность API Битрикс24, а не ошибка бота;
- у вебхука должны быть права на CRM (`scope=crm`), иначе Битрикс24 вернёт
  ошибку доступа, о чём бот сообщит текстом прямо на листе "Открытые линии" в
  отчёте.

Если понадобится более точная статистика (например, время до первого ответа,
оценки клиентов), обратитесь к разделу отчётов внутри самого Битрикс24
(Контакт-центр → Аналитика) — там эти данные доступны через интерфейс, даже
если REST API их не выгружает.

## Структура проекта

```
bitrix24-report-bot/
├── bot/
│   ├── bitrix/            # клиент REST API Битрикс24 и аналитика
│   │   ├── client.py       # HTTP-клиент вебхука с пагинацией и retry
│   │   ├── constants.py    # справочники статусов задач и т.п.
│   │   ├── tasks.py        # сбор и агрегация статистики по задачам
│   │   └── openlines.py    # сбор и агрегация статистики по Открытым линиям
│   ├── reports/
│   │   └── builder.py      # генерация Excel-отчёта (openpyxl)
│   ├── utils/
│   │   ├── period.py       # разбор периода из текста запроса
│   │   └── formatting.py   # общие форматтеры дат/чисел
│   ├── handlers/
│   │   ├── common.py       # /start, /help, клавиатура
│   │   └── report.py       # основной сценарий формирования отчёта
│   ├── middlewares.py      # ограничение доступа по Telegram ID
│   ├── config.py           # загрузка настроек из .env
│   └── bot.py              # точка входа (создание бота, polling)
├── tests/                   # unit-тесты (без обращения к реальному Битрикс24)
├── run.py                   # запуск: python run.py
├── requirements.txt
├── Dockerfile / docker-compose.yml
└── .env.example
```

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты покрывают разбор периода, агрегацию статистики по задачам и Открытым
линиям (на заглушках вместо реального Битрикс24) и генерацию Excel-отчёта.

## Диагностика проблем

| Проблема | Что проверить |
| --- | --- |
| Бот не отвечает | Процесс запущен? Верный `TELEGRAM_BOT_TOKEN`? Смотрите логи (`LOG_LEVEL=DEBUG`). |
| "У вас нет доступа к этому боту" | Добавьте свой Telegram ID в `TELEGRAM_ALLOWED_USER_IDS`. |
| Ошибка `INVALID_CREDENTIALS` / `insufficient_scope` от Битрикс24 | Проверьте `BITRIX_WEBHOOK_URL` и права (scope) вебхука. |
| Раздел "Открытые линии" пуст или содержит ошибку | См. раздел [про ограничения](#ограничения-и-особенности-статистики-открытых-линий). |
| Показывается статистика не того человека | Проверьте `BITRIX_DEFAULT_USER_ID` и `TELEGRAM_TO_BITRIX_USER_MAP`. |
